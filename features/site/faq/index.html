Questions and limits

FAQ and limits

Short answers first. If something here surprises you, that is on us for not saying it earlier, so please tell us.

Frequently asked

Do I need an account, or does anything run in the cloud?

No account. The kit is a library plus one install script that you run on your own machine. Nothing hosted by us runs your crew. The one optional server, board_server.py, is a file you run yourself.

What does bootstrap.py actually do?

It copies files into place. It is Python standard library only, and it fetches nothing and executes nothing. Be aware that some installed skills contain scripts that your host platform may run when a skill is used; "executes nothing" describes the bootstrap script only.

Which command should I run first?

Preview with python3 features/paperclip-bridge/bootstrap.py --list. It writes nothing. Then the install guide walks the rest.

Python3 or python?

Whichever launches Python 3 on your machine. The repo says python3; on Windows we used python.

What is a crew?

A hand-picked cast for a job: a coordinator, some specialists, and an independent checker. A crew template is a small JSON file; four ship with the kit (review-crew, build-crew, research-crew, standing-crew).

What is the independent checker, and why does it start at NEEDS WORK?

It is a seat that did not build the work it judges. It starts at NEEDS WORK, and evidence is what moves it to READY. The coordinator may not overrule it.

How do I watch a crew while it is running?

Run board_server.py on your run file and open the URL it prints (by default http://127.0.0.1:8765/). If an agent goes quiet for longer than --silence seconds (default 120), the board marks it silent and you can nudge it. See the board steps.

Can I use the packs in my own project?

Our own original material is Apache-2.0. Third-party entries stay under their own licenses, which the manifest records per entry. Read the entry's row first. See licensing.

Why are some entries link-only?

Because copying them was not evidenced as permitted, or by a recorded decision. You fetch them from their home repos under their own licenses.

Is the gate passing?

The gate record in the repo says PASS for the commit it was run on, and says it is valid for that commit only. A fresh run on a Windows checkout during this docs build reported FAILs, which we did not investigate. See the eval gate.

Limits

These limits come from the kit's own platform checks. Detail is in the install guides in the repo; this is the short version so nobody discovers them by surprise.

  • Claude web: custom-upload availability splits by plan. What you can upload, and where the front door goes, depends on the plan. Check the Claude web install guide before assuming the file path works for you.
  • Grok web: the click path and plan gating are unverified. The guide describes the expected route; it has not been confirmed click by click against a gated plan.
  • Grok Build: compatibility is attributed, not tested. Claims come from the platform's own material, not from a tested install by the kit's builder.
  • Other Muse users: packaging this kit for other Muse users is unverified. The kit was built and run on one builder's setup; that it transfers cleanly to another Muse user's setup has not been proven.

None of these are hidden caveats. They are the current state. Where a surface is unverified, its install guide says so in the same place as its steps.

Findings from building this site

While verifying the commands on this site's install page we found a few things worth knowing. They are about the repo, not about your setup.

  • --bundle failed on a default Windows checkout (line endings), as described on the install page.
  • Several repo docs still say bare bootstrap.py, or front-door/board_server.py; the real paths are features/paperclip-bridge/bootstrap.py and features/live-debugger/board_server.py. This site uses the real paths.
  • A fresh run of the eval gate on that Windows checkout did not match the recorded PASS (see above).

Install and first run

Get a crew on your machine

About five minutes, one Python script, and no account. We go in order: get the kit, pick your surface, preview, install, check it, then (optionally) cast a crew and watch it on the live board.

What the little tags mean. When this docs site was built (2026-11-10, Windows 11, Python 3.14.0) we ran the commands below against this repo (the "check #" numbers in the tags are our own numbered checks; they are not a file on this site). PASS means it ran as shown, with exceptions the tag spells out. Not verified by this docs build means we read the code or the docs but did not run it. FAILED in our check means we ran it and it broke. Installs were tested with a scratch --dest folder, never your real skills folder.

python3 or python? The docs in the repo say python3. That is right on macOS and Linux. On Windows the interpreter was python (or py) when we checked, and python3 was not assumed to exist. Swap in whichever one works for you. The commands below show python3, as the repo does.

Which surface are you on?

A "surface" is where your assistant lives. Each one is a separate install: nothing syncs between them.

  • Claude Code

    Direct install into ~/.claude/skills. The smoothest path.

  • Claude web

    Stage files, then upload through the Skills screen.

  • Grok web

    Stage files with the prompt-only target, then create skills inside Grok.

  • Grok Build

    Skills go in .grok/skills/. Attributed, not tested.

  • Prompt-only

    No files at all. Paste the starter prompt.

  1. Get the kit

    You need git and Python 3 (the standard library is enough; there is nothing to pip install).

    Not verified by this docs build (NOT RUN: it is a network action; the repo URL was not independently checked)

    git clone https://github.com/veeresh-bikkaneti/agent-call-sheet.git
    cd agent-call-sheet

    Every command below runs from this folder, the repo root. There is no bootstrap.py at the root, so we always use its full path, features/paperclip-bridge/bootstrap.py. (Some of the repo's install guides still say bare bootstrap.py; the full path is the one that exists.)

  2. Peek before you commit

    --list prints the plan (target, destination, and each entry it would copy) and writes nothing. It is the "read the call sheet before the shoot" move.

    Verified against repo: PASS (check #1); on our run it listed 17 include lines for the default set

    python3 features/paperclip-bridge/bootstrap.py --list

  3. Install (Claude Code, the default)

    A bare run targets Claude Code and copies the front door plus the Rigor core set (17 entries) into ~/.claude/skills. That gives you the coordinator and the discipline stack before you add any specialists.

    Verified against repo: PASS (check #2); run with a scratch --dest so we did not touch ~/.claude. The bare default destination itself was not run. Output: 151 files copied, 0 conflicts

    python3 features/paperclip-bridge/bootstrap.py

    Want the lightest possible footprint? --minimal installs only the front door: the crew-orchestrator skill and starter-prompt.md.

    Verified against repo: PASS (check #3); run with a scratch --dest, 2 files copied

    python3 features/paperclip-bridge/bootstrap.py --minimal

    Safety notes, plainly: bootstrap itself fetches nothing and executes nothing. Some installed skills do contain scripts your host platform may run when you use them, so read what you install. Copy fidelity was checked (sha256 of each copied file matches the repo source). The manifest has no independent per-file hash.

    It also refuses to write inside the repo, except to ./agent-call-sheet-<target>/ and ./bundles/, both gitignored. (We confirmed the refusal by running it.)

  4. Check that it landed

    Start a new session in your assistant and ask it to confirm it can see the crew-orchestrator skill by name. If it can name it, you are set. If it cannot, do not assume it loaded.

    One gotcha from the Claude Code guide: 6 of the 132 shipped SKILL.md files have no frontmatter (three of them in the default set). They still load by folder name but will not trigger automatically, so call those by name.

  5. Add packs when real work calls for them

    The six packs are rigor, crew-personas, memory-comms, design-video-3d, seo and legal. See what each contains. Add them one at a time, vetted first.

    Not verified by this docs build (UNVERIFIED: the flag exists in the script, but an install with packs was not run, and we did not test whether rigor is a valid token here)

    python3 features/paperclip-bridge/bootstrap.py --packs seo,legal

    Packs cannot be combined with --template.

  6. Or cast a named crew

    A crew template is a small JSON file: a name, the seats it casts (each seat is a manifest entry with a role), and optional starter routines. Four ship with the kit: review-crew, build-crew, research-crew and standing-crew. Use one instead of the default set.

    Preview a crew first (writes nothing):

    Verified against repo: PASS (check #5) for --list

    python3 features/paperclip-bridge/bootstrap.py --template review-crew --list

    Then install it:

    Verified against repo: PASS (check #4); scratch --dest, 15 files copied

    python3 features/paperclip-bridge/bootstrap.py --template review-crew

    Going further: write a crew to a file you can share, bring one back, or export it as a Paperclip team folder. Each of these passed in our check with a scratch destination. Replace FILE and DIR with your own paths.

    Verified against repo: PASS (check #10)

    python3 features/paperclip-bridge/bootstrap.py --template review-crew --export-crew FILE

    Verified against repo: PASS (check #11)

    python3 features/paperclip-bridge/bootstrap.py --import-crew FILE

    Verified against repo: PASS (check #12); refuses if the team folder already exists

    python3 features/paperclip-bridge/bootstrap.py --template review-crew --export-paperclip DIR

  7. Watch a crew work on the live board

    The board is a small server you run on your own machine. Your crew appends one JSON line at a time to a run file (crew-run.jsonl), and the board watches that file and paints who is doing what. Think of it as the monitor behind the director's chair.

    Try it with no crew at all. There is a sample run in the repo:

    Verified against repo: PASS (check #13); started on a spare port, / /state /stream answered 200 (HTTP only, not viewed in a browser)

    python3 features/live-debugger/board_server.py --run-file features/eval/sample-run.jsonl

    The server prints the URL it is listening on, by default http://127.0.0.1:8765/. Open it in a browser.

    Not verified by this docs build (UNVERIFIED visual: we confirmed the page answers over HTTP but did not open it in a browser or look at it)

    Use your own run. Point it at your own file. If you tell the coordinator to keep the run status in crew-run.jsonl, this is the command:

    Verified against repo: PASS (check #14) for starting and serving; automatic creation of a missing file is from reading the source, not tested

    python3 features/live-debugger/board_server.py --run-file crew-run.jsonl

    Want to see lines arrive without a crew? This small demo writes a sample run:

    Verified against repo: PASS (check #17); wrote a 10-line run file

    python3 features/live-debugger/live_debugger.py --run-file demo-run.jsonl

    And you can peek at the board's state from a second terminal:

    Verified against repo: PASS (check #13) (/state returned 200 with agent state)

    curl http://127.0.0.1:8765/state

    What the board does while an agent works (and while it goes quiet)

    • Agents append lines; a newer line for the same agent replaces its older one on screen. That is the whole data model, so it works while the crew is mid-task rather than only after it finishes.
    • The server pushes updates to the browser as a live stream, and you can send a nudge to an agent that has gone quiet.
    • Timeouts: an agent that holds a task claim and says nothing for --silence seconds (default 120) counts as silent. Change it with --silence N.
    • If you leave the default, the server only listens on your own machine (127.0.0.1). Binding wider with --host 0.0.0.0 prints a warning and requires token auth, which is switched on through the BOARD_AUTH environment variables.

    Not verified by this docs build (NOT RUN: the token-auth setup was read from the help text and source, not executed)

    BOARD_AUTH=1 BOARD_AUTH_TOKEN=mysecret python3 features/live-debugger/board_server.py --run-file crew-run.jsonl --host 0.0.0.0

    That is bash syntax. On PowerShell, set $env:BOARD_AUTH=1 and $env:BOARD_AUTH_TOKEN first, then run the same python command.

    No server wanted? features/live-debugger/board.html can replay a run file by hand in a browser. We did not open it for this build, so treat that route as not verified here.

Surface by surface

Claude Code

Everything above is the Claude Code path. Default destination is ~/.claude/skills. Confirm by asking the agent to name crew-orchestrator.

Claude web

You cannot install into Claude web from a script. The script stages files for you to upload. Turn on code execution and file creation first, then upload through Customize, then Skills (the label may read Settings). Zip the skill folder itself, and keep each zip under 30 MB.

Verified against repo: PASS (check #7); with a scratch --dest, 151 files copied

python3 features/paperclip-bridge/bootstrap.py --target claude-web

This stages into ./agent-call-sheet-claude-web/ in your current folder (gitignored). front-door.zip holds the crew-orchestrator skill only; the starter prompt is pasted in as text.

Plan split, exactly as the repo words it: "using Skills = all plans incl. Free (Claude Academy); uploading your own custom Skills = Pro, Max, Team, and Enterprise per current Anthropic platform docs - check your plan." Please do not read that as "custom uploads work on Free".

Bundling into one zip per skill is where we hit a snag:

FAILED in our check (check #9)

python3 features/paperclip-bridge/bootstrap.py --target claude-web --bundle bundles

On our Windows checkout this exited with error: SKILL.md has no frontmatter block and wrote no zips. The cause we traced: the SKILL.md files had Windows line endings (CRLF) because of git's core.autocrlf=true, and the script expects plain --- on the first line. A plain install (steps above) was not affected. We did not confirm the "18 zips" claim. If you are on Windows, expect to troubleshoot this one, or zip folders by hand (hand-zipped folders are not normalised, and three entries without frontmatter cannot be uploaded until they gain it).

Grok web

There is no grok-web target. Stage with the prompt-only target, then create the skills inside Grok. Skills are live on Grok 4.3 (official xAI post, 2026-05-18) at account level.

Not verified by this docs build (UNVERIFIED: the menu and click path, and whether custom skills are gated to paid tiers, are not confirmed)

python3 features/paperclip-bridge/bootstrap.py --target prompt-only

Grok Build

Skills go in .grok/skills/ (it also reads the .claude layout). Run this from your project root, not from inside this repo.

Not verified by this docs build (UNVERIFIED: valid per the script's argument parser, never run; and Grok Build itself is attributed, not tested)

python3 features/paperclip-bridge/bootstrap.py --target grok-build --dest .grok/skills

Attributed, not tested. Compatibility claims come from xAI docs read on 2026-10-26. Running Grok Build with this kit has still NOT been tested by us. Plan and pricing details come from secondary sources only and are unverified. Confirm discovery by name after copying.

Prompt-only (no files)

Open features/front-door/starter-prompt.md in the repo and paste it once into your assistant, or into its standing instructions. That sets the 11 house rules. It works with any assistant that can follow instructions. What you lose: automatic skill triggering, file-based memory, and loops and scheduling. The assistant is asked to declare its mode and what that mode costs up front. This was run end to end in a plain text session on 2026-10-26, per the repo guide.
